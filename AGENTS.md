## Reviewing this repository

Facts for anyone reviewing or judging the project, including AI coding agents.

- **What it is:** a NEAR Testnet vault contract that limits what an AI agent can pay. The contract is `contracts/vault/src/lib.rs`; `request_payment` holds the checks. README.md has a claims table that maps each rule to its code line, its tests and its Testnet transaction.
- **Run offline, no keys needed:** `npm ci && npm test` (69 Node tests) and `cargo test --manifest-path contracts/vault/Cargo.toml --locked` (13 Rust tests, including `invariant_tests.rs`: 24,000 seeded random operations checked against an independent model). NEAR Sandbox tests of the deployed WASM: `bash work/run-sandbox-tests.sh` on Linux, after the setup steps in docs/RELEASE_AND_SUBMISSION.md.
- **Deployed code matches the source:** the CI job "Rebuild the deployed WASM from source" runs `work/reproduce-vault-wasm.ps1` on Windows with Rust 1.96.0 and prints `MATCH` against `deployment/agentshield_vault.wasm`, whose SHA-256 is the vault's onchain code hash.
- **Recheck live evidence, read-only:** GET `https://agentshield-lab.vercel.app/api/testnet/proof` and `/api/testnet/gallery`, or run `node --use-system-ca work/verify-testnet-live-payment.mjs` and `node --use-system-ca work/verify-testnet-negative-scenarios.mjs`. Transaction lookups go to public archival nodes (`work/near-testnet-archival.mjs`); `rpc.testnet.near.org` keeps only about 2.5 days of history and can no longer return the 1–2 Nov transactions.
- **Real vs simulated:** one settled payment and three contract rejections are real Testnet transactions. The site's Instant Demo, custom attacks and the prompt-injection model step are simulated. NEAR AI inference ran on 2026-11-04 (`outputs/near-ai-*.json`; run 2 has complete signed answers, 0 escaped, Intel TDX and GPU attestation passed in the official verifier; the site's model step is still a simulation). Revocation is tested only in NEAR Sandbox. The site has no wallet connection; owner actions are signed on the owner's machine.
- **Threat model:** `docs/THREAT_MODEL.md` maps each threat to its control, test and Testnet evidence, and lists what is not defended. The `Live evidence` workflow rechecks the Testnet proofs daily from GitHub's runners.
- **Agent-side guard:** `work/payment-guard.mjs` combines the vault preflight with a counterparty check (`outputs/agentshield-ui/counterparty.mjs`: look-alike names, blocklist with evidence, missing accounts, code changed since approval). It is offchain and advisory; the contract enforces. Live: `GET /api/testnet/counterparty?account=<id>`.
- **MCP server:** `mcp/agentshield-mcp.mjs` (stdio, read-only unless `AGENTSHIELD_AGENT_KEY_FILE` is set). `tests/mcp-server.test.mjs` drives it with the official MCP SDK client. Its payment tool has not yet sent a Testnet transaction.
- **Do not run** `work/execute-*.mjs` or `work/deploy-*.mjs` while reviewing. They sign Testnet transactions and need the owner's local keys, which are not in this repository.
