# Judge walkthrough

No wallet or account is needed for the public proof path. Open [AgentShield Lab](https://agentshield-lab.vercel.app/) in a clean browser.

For a guided version, open **Judge mode** (`/#judge`) and press **Watch AgentShield in action**. It is a six-scene illustrated replay of the same records, about 70 seconds long, and every fact is labelled `SIMULATION`, `HISTORICAL ONCHAIN REPLAY`, `LIVE RPC VERIFIED`, or `NOT YET VERIFIED`. **Attack the vault** (`/#attack`) replays the nine recorded Testnet scenarios (two payments, seven attacks) with a live recheck button, runs custom attacks in the simulator, and walks through a prompt-injection challenge whose scripted model step is simulated. Under it, **Now try the real model** sends your own note to the real model on NEAR AI Cloud, checks the reply's TEE signature and runs the guard; it never signs or sends anything.

1. On **The Thesis**, read the contract-held vault summary and open **Instant Demo**. Run its five scenarios. The screen labels these as simulation; they are not five onchain transactions.
2. Open **Evidence**. Wait for **“One payment. Independently verified.”** Open **VIEW LIVE JSON PROOF**. Expect `verification: PASS`, `settlement: SETTLED`, the deployed vault code hash, the restricted signer, transaction `3buDvB…53jm`, and transfer receipt `76hE3j…K2dS`. The initial `AUTHORIZED` decision alone is not the settlement claim. Below it, **A second payment, sent by an agent through the MCP server** rechecks `HP3Bfd…uGuRk` the same way.
3. Continue down **Evidence** to the seven rejection proofs. Expect `PER_PAYMENT_LIMIT`, `RECIPIENT_NOT_ALLOWED` and `REPLAY` (mandate version 1), then `STALE_VERSION`, `EXPIRED`, `RECIPIENT_NOT_ALLOWED` for the look-alike `…1o77`, and `WRONG_AGENT` for a request signed by the owner (version 2), each with a finalized Testnet transaction and zero vault transfer receipts. **Revocation** is marked not yet verified on Testnet; it passes in NEAR Sandbox against the deployed WASM.
4. Open **Lab** to inspect public Testnet account and vault state. Further down, **Check a receiver before paying** runs the counterparty check live: try the six redirect targets from the recorded attacks. Expect `ALLOW` for the real recipient and `BLOCK` for each attack, with the reason (for example, an `o` in place of a `0`, or a Cyrillic `і` highlighted). The site has no wallet connection and never asks you to sign anything; owner actions are signed on the owner's own machine. Nothing to approve in this walkthrough.
5. For independent reproduction, run the read-only verifier commands in [README](../README.md) or query the archival node `https://archival-rpc.testnet.near.org` directly for the hashes (the regular `rpc.testnet.near.org` keeps only about 2.5 days of history) in [the evidence table](ARCHITECTURE_AND_EVIDENCE.md). An explorer may block automated requests. The **Live evidence** GitHub Actions workflow runs the same verifiers every day from GitHub's machines.
6. For why each check exists, read [THREAT_MODEL.md](THREAT_MODEL.md): every threat, the control that stops it, the test, the evidence, and what is not defended.

## Expected limits

- The **Mandate** form saves a browser-only draft. It does not set the deployed policy.
- Owner controls are not a browser signing flow: the owner signs on their own machine.
- The counterparty check is an offchain warning layer; the contract's allowlist is what enforces. Account age and past payments are not checked.
- The MCP server's payment tool has made one settled Testnet payment (the `ALLOW` path). Its `WARN` (human approval) and `BLOCK` paths are tested with the official MCP SDK client and a stand-in signer, not on Testnet.
- The AI agent has strict output validation and mocked injection coverage. On 2026-11-04, 24 real NEAR AI Cloud completions (`z-ai/glm-5.3-flash`) were recorded with signatures that recover to the attested model key; the Intel quote is not verified, and the 180-token limit cut off 22 of 24 replies, which the preflight blocked. On 2026-11-04 a second run (22 completions, 1,024-token limit, `z-ai/glm-5.3-flash`) returned complete answers: the model ignored the injected note, 11 of 19 red-team attacks returned the original payment, 4 returned empty fields, 4 ran out of tokens, none proposed the attacker's account or amount, and 0 escaped. NEAR AI's official verifier passed the Intel TDX and NVIDIA GPU attestation for the signing key. The site's prompt-injection model step stays simulated, with the real result shown under it.
- The owner renewed the mandate on 2026-11-03 as version 2, with the same rules, until **2026-11-30 00:00 UTC**. The first payment and the first three rejections ran under version 1; the MCP payment and the four later rejections ran under version 2. All of them stay independently verifiable after expiry.
